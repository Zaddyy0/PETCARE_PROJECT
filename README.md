# Pawsitively Perfect

Pawsitively Perfect is a full-stack pet care platform rebuilt from the original static prototype into a MERN application.

The app keeps the same core flow as the original project:
- user login and signup
- pet profile creation, editing, deletion, and photo uploads
- appointment booking
- drag-and-drop appointment tracking
- pet detail pages with related bookings

## Tech Stack

### Frontend
- React
- Vite
- Tailwind CSS
- React Router
- Axios

### Backend
- Node.js
- Express
- MongoDB with Mongoose
- JWT authentication
- Multer for photo uploads

## Project Structure

- `frontend/` contains the React + Vite frontend
- `server/` contains the Express API and MongoDB models
- `dist/` is generated by the frontend production build

## Setup

### 1. Install dependencies

```bash
npm install
```

### 2. Configure environment variables

Create `server/.env` from `server/.env.example` and set:
- `MONGODB_URI`
- `JWT_SECRET`
- `CLIENT_ORIGIN`
- `PORT`

Optional frontend config can be added in `.env` if you want a different API base URL:
- `VITE_API_URL`

### 3. Start MongoDB

Use a local MongoDB instance or a hosted MongoDB connection string.

### 4. Run the app in development

Start the frontend from the repository root:

```bash
npm run dev
```

In a separate terminal, start the backend from the `server/` folder:

```bash
cd server
nodemon
```

## Demo Account

## Production Build

```bash
npm run build
cd server
npm start
```

The frontend build is produced at the repository root, and the Express server can be started independently from `server/`.

## Main Features

- secure login and signup
- pet profile CRUD with image uploads
- appointment creation and status transitions
- dashboard summary cards
- responsive UI with a custom Tailwind theme
- seeded demo content for immediate testing
- input validation for auth, pet, and appointment APIs
- rate limiting on authentication routes
- explicit confirmation required before pet deletion

## API Overview

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/auth/me`
- `GET /api/pets`
- `POST /api/pets`
- `PUT /api/pets/:id`
- `DELETE /api/pets/:id`
- `GET /api/appointments`
- `POST /api/appointments`
- `PATCH /api/appointments/:id/status`

## Notes

- Uploaded pet photos are stored locally in `server/uploads` by default.
- The app uses JWT bearer tokens stored in local storage for simplicity.
- The project is structured so the frontend can be deployed separately or served by the backend in production.
- Frontend and backend run independently in development (separate terminals/processes).
